> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para executar este plano tarefa por tarefa. Os passos usam checkbox (`- [ ]`).

**Objetivo:** repositório com CI, pacote `core` com a Score IR completa e JSON Schema publicado, e pacote `eval` capaz de medir notas e notação, rodando ponta a ponta sobre um "transcritor nulo".

**Arquitetura:** workspace `uv` com dois pacotes Python (`transcritor_core`, `transcritor_eval`) em layout `src/`. O `core` define o contrato (Pydantic v2) sem dependências de áudio. O `eval` lê um manifesto de dataset versionado, gera referências a partir de MusicXML + downbeats, calcula métricas com `mir_eval`/music21 e compara com uma linha de base versionada (portão de CI).

**Stack:** Python 3.12, uv, Pydantic 2.14, music21 10.5, mir_eval 0.8, soundfile, numpy, ruff, mypy, pytest, pip-licenses, GitHub Actions.

**Spec:** `docs/roadmap/fases.md` (F0), `docs/arquitetura/score-ir.md`, `docs/arquitetura/stack.md`, `docs/arquitetura/licencas.md`, `docs/modulos/core.md`, `docs/modulos/eval.md`. Ler antes de começar.

## Restrições globais

- Python `>=3.12,<3.13`; gerenciador `uv`; um pacote por módulo em `packages/<modulo>/src/transcritor_<modulo>/`, testes em `packages/<modulo>/tests/`.
- `ruff check`, `ruff format --check`, `mypy --strict` (pacotes), `pytest` devem passar em toda tarefa.
- Pydantic v2; todos os modelos com `model_config = ConfigDict(extra="forbid")`.
- `SCHEMA_VERSION = "1.0.0"`.
- Código, identificadores e commits em inglês (Conventional Commits); docs em português.
- Só dependências com licença permitida em `docs/arquitetura/licencas.md`; nenhuma AGPL ou NC.
- Áudio real nunca entra no git (`data/` é ignorado); referências (CSV/MusicXML), manifestos e linhas de base **são** versionados.
- Toda mensagem de commit termina com as linhas de atribuição do projeto (Co-Authored-By / Claude-Session) quando feita por agente.

## Ajustes de spec decididos neste plano

1. **Local do dataset e da linha de base.** `eval.md` dizia `data/eval/manifest.json` e `data/eval/baseline.json`, mas `data/` é ignorado pelo git. Decisão: manifestos e referências em `packages/eval/datasets/<nome>/`, linhas de base em `packages/eval/baselines/<subset>.json`; só o áudio real fica em `data/eval/audio/`. O conjunto `ci` (sintético, CC0, criado por nós) tem áudio versionado.
2. **Significado de `beat` em `NotatedElement`.** Fixado como: deslocamento desde o início do compasso, em frações de semibreve. Compassos numerados a partir de 1; anacruse = compasso 0.
3. **`--stage` do CLI de eval** fica para a F1; na F0 existe `--pipeline null`.
4. **MPL-2.0** (certifi, dependência transitiva) entra na lista de permitidas (uso sem modificação).
5. **Geradores de casos de teste** (performances simbólicas e áudio sintético, `eval.md`) ficam para a F1, junto com os módulos que testam (`notate`, `listen`, `rhythm`). A F0 só cria o conjunto `ci` sintético mínimo.
6. **Referência de downbeats** de cada item é versionada junto do manifesto; ela alimenta tanto o alinhamento das notas quanto a métrica de ritmo.

A Tarefa 14 grava esses ajustes nos `.md`.

## Foco de revisão

1. Documento com `schema_version` de major desconhecido → `SchemaVersionError` com a versão no texto, não um erro genérico do Pydantic. (Tarefa 5)
2. Frações musicais (1/3, 3/8) sobrevivem a dump/load sem virar float. (Tarefa 2 e 5)
3. Item do manifesto sem áudio local → relatório marca o item como `skipped` com o caminho esperado e segue; no subset `ci` isso é erro. (Tarefa 12)
4. Referência com anacruse e com ligaduras atravessando a barra → onsets corretos e nota ligada contada uma vez só. (Tarefa 9)
5. Quantidade de downbeats incompatível com o número de compassos → erro explícito dizendo quantos eram esperados. (Tarefa 9)

### Tarefa 9: Referência de notas a partir de MusicXML + downbeats

Serve para o usuário anotar gravações reais: ele marca o início de cada compasso (por exemplo, rótulos no Audacity ou no Sonic Visualiser) e o sistema calcula o tempo de cada nota.

**Arquivos:** criar `align.py`; teste `test_align.py` com MusicXML pequenos montados com music21 no próprio teste.

**Interfaces — consome:** `RefNote`. **Produz:**
- `read_downbeats(path: Path) -> list[float]`: aceita um número por linha **ou** o formato de rótulos do Audacity (tab-separado, primeira coluna); ignora linhas vazias; exige ordem estritamente crescente.
- `reference_notes_from_score(score_path: Path, downbeats_s: list[float], part_index: int = 0) -> list[RefNote]`
  - `downbeats_s` = início de cada compasso (incluindo a anacruse, se houver) **+ o instante final** do último compasso; esperado `len == n_compassos + 1`, senão `ValueError("expected N+1 downbeats (N measures + end time), got M")`.
  - Dentro de cada compasso, interpolação linear: `t = t_ini + (offset / duração_real_do_compasso) * (t_fim - t_ini)`, usando a duração real do compasso no music21 (a anacruse tem duração menor que o compasso cheio).
  - Ligaduras: notas ligadas viram uma `RefNote` só (início da primeira, fim da última). Pausas e notas de enfeite são ignoradas. `pitch_midi` = altura **soante** (aplicar transposição se a parte for transpositora).
- `write_reference_notes(notes: list[RefNote], path: Path) -> None`.
